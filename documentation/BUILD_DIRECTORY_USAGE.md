# Building FlightView in a Separate Build Directory

## Overview

The `build_with_metal.sh` script now supports out-of-source builds. You can run it from any directory, and it will:

1. Detect the source directory (where the script is located)
2. Build in your current directory (the build directory)
3. Place all build artifacts in the build directory

## Usage Examples

### Example 1: Build in ../build

```bash
# From your source directory
cd /Users/eliggett/Documents/liveview/20260126/FlightView

# Create and go to build directory
mkdir -p ../build
cd ../build

# Run the build script from source directory
../FlightView/build_with_metal.sh
```

**Result:**
- Source files remain in `../FlightView/`
- Build artifacts created in `../build/`
- Metal shader: `../build/std_dev_filter.metallib`
- Application: `../build/lv_release/liveview` (or `../build/liveview`)

### Example 2: Build in ~/builds/flightview

```bash
# Create build directory anywhere
mkdir -p ~/builds/flightview
cd ~/builds/flightview

# Run script with full path
/Users/eliggett/Documents/liveview/20260126/FlightView/build_with_metal.sh
```

**Result:**
- Build artifacts in `~/builds/flightview/`
- Source untouched

### Example 3: Clean rebuild

```bash
cd ../build

# Clean previous build
rm -rf *

# Rebuild
../FlightView/build_with_metal.sh
```

## What the Script Does

1. **Detects directories:**
   ```
   Source directory: /path/to/FlightView
   Build directory: /path/to/build
   ```

2. **Compiles Metal shader:**
   - Reads from: `$SOURCE/backend/src/std_dev_filter.metal`
   - Writes to: `$BUILD/std_dev_filter.metallib`

3. **Builds backend library:**
   - Builds in: `$SOURCE/backend/` (creates object files there)
   - Creates: `$SOURCE/backend/lib_backend.a`

4. **Builds FlightView:**
   - Runs qmake in: `$BUILD/`
   - Creates Makefile in: `$BUILD/`
   - Builds in: `$BUILD/`
   - Output: `$BUILD/lv_release/` or `$BUILD/`

5. **Installs Metal shader:**
   - Copies to: `$BUILD/lv_release/std_dev_filter.metallib`
   - And to: `$BUILD/lv_release/liveview.app/Contents/MacOS/` (if app bundle)

## Directory Structure After Build

```
FlightView/                          (source - unchanged)
├── backend/
│   ├── obj/                        (object files)
│   └── lib_backend.a              (static library)
├── build_with_metal.sh
└── ...

build/                               (build directory)
├── Makefile                        (generated by qmake)
├── std_dev_filter.metallib        (Metal shader)
├── lv_release/
│   ├── liveview                   (application)
│   ├── std_dev_filter.metallib   (copy for runtime)
│   └── liveview.app/              (if app bundle)
├── *.o                             (object files)
└── moc_*.cpp                       (Qt generated files)
```

## Running the Application

After building in `../build`:

```bash
cd ../build/lv_release

# The Metal library is already in the right place
./liveview --headless --rtpnextgen --rtpwidth 1280 --rtpheight 328 \
  --no-gps --skipframes 3 --rtpinterface lo0
```

Or if built directly in build directory:

```bash
cd ../build

./liveview --headless --rtpnextgen --rtpwidth 1280 --rtpheight 328 \
  --no-gps --skipframes 3 --rtpinterface lo0
```

## Advantages of Out-of-Source Builds

1. **Keep source clean**
   - No build artifacts in source tree
   - Easy to diff and commit

2. **Multiple build configurations**
   ```bash
   mkdir -p ~/builds/flightview-debug
   mkdir -p ~/builds/flightview-release
   # Build different configs in different directories
   ```

3. **Easy to clean**
   ```bash
   rm -rf ../build/*
   # Source directory untouched
   ```

4. **Safe**
   - Accidental `make clean` won't delete source
   - Build errors won't corrupt source

## Troubleshooting

### "ERROR: std_dev_filter.metal not found"

The script couldn't find the source files. Make sure you're using the correct path to the script.

**Check:**
```bash
# Where is the script?
ls -l ../FlightView/build_with_metal.sh

# Does the metal file exist?
ls -l ../FlightView/backend/src/std_dev_filter.metal
```

### Build artifacts in source directory

The `backend` library still builds in the source directory (creates `obj/` and `lib_backend.a` there). This is normal - the main application builds in your build directory.

To clean backend:
```bash
cd /path/to/FlightView/backend
make clean
```

### Metal library not found at runtime

Make sure you run from the build directory or that `std_dev_filter.metallib` is in the same directory as the executable:

```bash
# Check it's there
ls -l lv_release/std_dev_filter.metallib

# Or
ls -l std_dev_filter.metallib
```
